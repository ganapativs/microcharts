### Batch 3 — premium polish pass & learnings (2026-07-09) — handoff to the next agent

All 22 expressive charts shipped; this pass was a user-driven craft review. Fixes landed on `batch-3-expressive` (component + geometry + docs demo + test in each case; verified against the SSR `scripts/visual-check.mjs` harness by reading rendered SVG coordinates, not screenshots — screenshots of the static `vcheck.html` don't capture in this preview).

**Fixed (root cause → fix):**
- **Hourglass** — glass box used a *fixed* `width ?? 16` while demos only set `height`, so tall demos rendered a thin sliver. → default width now tracks height: `width ?? max(12, round(height*0.66))`. The one true "stretch" bug in the batch.
- **CitySkyline** — category labels hugged the ground line (~1px). → `botPad = fontSize + 4` (a *constant* gap, not em-scaled — an earlier em-scaled gap inflated botPad to 21px on tall/large-font demos and squished buildings to 7px; buildings must win).
- **Honeycomb** — filled cells tessellate edge-to-edge and merged into one borderless blob (the comb structure — the whole point — vanished). → draw each hex at `r*0.85` so a gutter separates every cell; empty-outline strokeOpacity 0.5 → 0.75.
- **Constellation** — `label="max"` numeral clamped onto the star when the star sat near the top edge. → numeral is `anchor="middle"`, centred on the star, lifted clear of the halo ring (drops below when the top is tight).
- **MusicStaff** — note-heads read as squished circles. → tilt them `rotate(-22)` (real engraved note-heads are tilted ovals); the tilt makes the ovalness read as intentional. Rotated extent stays within the ry/rx band insets (checked).
- **FillWord** — numeral sat in dead space and the fill was low-contrast. → numeral gutter `0.5em → 0.3em` (hugs the word's real 0.56-em extent, inside the 0.62 containment estimate); base "track" word faded to `fillOpacity 0.4` so the accent copy reads as clearly advanced. **Open:** the "animation not visible" complaint is about the *interactive* entry — verify `fill-word/client.tsx` actually animates the clip and isn't over-gated.
- **SproutRow** — labels overlapped. Owner: the user finished this one live — two-tier **stagger** (even slots near the soil, odd slots dropped one line + a faint leader tick), `step = max(props.step, ceil(catExtent/2))`, `padX` side-gutter so end labels don't clip. Don't revert.

**Learnings to carry into Batch 4 (frontier):**
1. **Aspect ratio is a *geometry* invariant, not a CSS one.** `Chart` sets `preserveAspectRatio="xMidYMid meet"`, so CSS can never distort content — any "stretched/oval" chart is a bad intrinsic viewBox. The trap: a fixed default on ONE axis while demos drive the OTHER. Radial charts avoid it by construction (single `size` → width==height); Thermometer avoids it by branching on orientation. Audit every new chart: does its default width track its default height (or vice-versa)?
2. **Merged O(1) paths lose internal structure.** When you merge marks into one `<path>` for node budget (honeycomb, tally, city windows), a shape that should read as *many cells* becomes one blob. Inset the draw radius / add gutters so the unit-count still reads.
3. **Don't shrink text below the ~7px legibility floor to make it fit** (`labelFont` floors at 7). Widen the canvas, stagger onto tiers, or drop labels — never render 4px captions. (Sprout-row started as widen, user chose stagger; both honest.)
4. **Gaps/pads that scale with `fontSize` can starve the primary mark** when the font is large on a big demo. Prefer a small constant for breathing gaps; reserve em-scaling for the text's own box.
5. **Verify by reading rendered SVG coordinates** from the `visual-check.mjs` output (`node scripts/visual-check.mjs` → `apps/docs/public/vcheck.html` → inspect `svg.mc-root` attrs). Exact and reliable; static-file screenshots are flaky in this preview.
