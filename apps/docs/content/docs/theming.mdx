title: Theming
description: Theme microcharts with ~20 CSS custom properties and named presets — override a token at any scope, switch presets with a data attribute, keep semantic colors meaning what they say, and get hand-tuned dark mode and forced-colors support for free.

microcharts theming is CSS custom properties, all the way down. There's no theme provider to
wire up and no Tailwind requirement — set a `--mc-*` variable at any scope and every chart
inside it retunes, with zero re-render and no build step.

## Override a token

```css
.brand {
  --mc-accent: #7c3aed;
  --mc-stroke-width: 2;
}
```

Every chart inside `.brand` now draws with that accent and stroke weight. Precedence is
predictable: a **prop** wins over a **CSS-variable scope**, which wins over a **preset**, which
wins over the built-in default.

## Scope it anywhere

Because the tokens cascade, the scope is yours to choose — the whole app, one brand section, a
single card, or one chart. Set a token high and every chart below inherits it; override it
lower and only that subtree changes.

```tsx
// app-wide, once
<html style={{ "--mc-accent": "var(--brand-500)" }}>

// just this card's charts
<div style={{ "--mc-stroke-width": 2, "--mc-radius": 3 }}>
  <SparkBar data={weekly} />
</div>
```

Bind `--mc-accent` to your existing brand variable and the charts follow your design system
automatically — no per-chart props, no duplicated color values.

## Presets

Presets are bundled token sets, applied with a `data-mc-theme` attribute — pure CSS, zero
JavaScript. They change how charts _look_, never what the data _means_.

## The token set

Around twenty custom properties cover the whole surface. Set any of them at any scope and every
chart inside retunes. Here's the full set with its defaults, grouped by what it controls and why
it exists:

```css
:root {
  /* ── Semantic colour — encodes MEANING, never decoration ─────────────── */

  /* Default ink: lines, bars, labels. Dark mode ships a hand-tuned value,
     not an inversion. */
  --mc-stroke: #171717;

  /* The "good" direction — a colour-blind-safe green, always paired with a
     ▲ so meaning never rests on colour alone. */
  --mc-positive: #009e73;

  /* The "bad" direction — colour-blind-safe vermillion, paired with a ▼. */
  --mc-negative: #d55e00;

  /* No-signal marks: baselines, inactive points, empty cells. */
  --mc-neutral: #8a8a8a;

  /* The single emphasis colour — one highlighted series or endpoint.
     Rebind this to your brand. */
  --mc-accent: #0072b2;

  /* Normal-range shading, derived from the ink so it always matches. */
  --mc-band: color-mix(in oklab, var(--mc-stroke) 8%, transparent);

  /* ── Categorical palette — only for the rare multi-series chart ────────
     Six hues that stay distinguishable across the common colour-vision
     types AND in greyscale/print. Ordered high-contrast-first, so a 2- or
     3-series chart reaches for the most separable pair first. */
  --mc-cat-1: #e69f00;
  --mc-cat-2: #56b4e9;
  --mc-cat-3: #009e73;
  --mc-cat-4: #0072b2;
  --mc-cat-5: #d55e00;
  --mc-cat-6: #cc79a7;

  /* ── Geometry — treats size as a design material ───────────────────────*/

  /* Light by default so a chart reads at text weight inline; bump to
     ~2 when it stands alone. */
  --mc-stroke-width: 1.5;

  /* Spacing between grouped marks; em-based so it scales with the font. */
  --mc-gap: 0.25em;

  /* Direct-label text size, relative to the chart's font. */
  --mc-label-size: 0.75em;

  /* ── Motion & type — applied only where it earns its place ─────────────*/

  /* Entrance timing for interactive entries; static charts never animate
     (zero client JS). */
  --mc-duration: 300ms;

  /* Ease-out: marks decelerate into place, never bounce or loop. */
  --mc-easing: cubic-bezier(0.22, 1, 0.36, 1);

  /* Charts borrow your UI font + tabular numerals by default; pin a family
     here to override. */
  --mc-font: inherit;

  /* ── Interactive readout surface — the only opaque plane a mark sits on ──
     The value chip shown on hover/focus. Defaults to the system canvas so it
     adapts with no config; point these at your popover tokens to match a
     themed surface. */
  --mc-surface: Canvas;
  --mc-surface-ink: CanvasText;
  --mc-surface-edge: color-mix(in oklab, CanvasText 16%, transparent);
}
```

## Semantic vs categorical color

Two rules make theming predictable and keep it honest.

**Semantic tokens keep their meaning.** Swapping `--mc-accent` retints the one emphasis color,
but `--mc-positive`/`--mc-negative` still mean up and down — so a preset can restyle a chart
without ever changing what it says. Color encodes; it never merely decorates.

**Categorical colors are a last resort.** Most microcharts show one series and never touch the
palette. When a chart genuinely needs several, the six `--mc-cat-*` hues are ordered
high-contrast-first and chosen to survive color-vision differences _and_ grayscale print — so a
two-series chart automatically reaches for the most separable pair.

## The readout surface

The only opaque plane in the whole library is the value chip an interactive chart shows on
hover or focus. Its three `--mc-surface*` tokens default to the system `Canvas`, so it adapts to
light, dark, and forced-colors with no configuration. Point them at your popover tokens when you
want the chip to match a themed surface exactly.

## Dark mode and forced colors

Dark values are hand-tuned per token — never auto-inverted, so overriding one light value can't
quietly break the dark surface. microcharts follows `prefers-color-scheme` out of the box, and
you can force a scope with `data-mc-theme="dark"`. Charts never paint their own background, so
they always sit cleanly on your surface.

Under Windows High Contrast (`forced-colors`), the semantic tokens defer to system colors —
ink to `CanvasText`, accent to `Highlight`, muted marks to `GrayText` — so a chart stays legible
even when your palette is overridden entirely.
