## Set up with an AI agent

Prefer to automate it? Hand this prompt to your coding agent — **Cursor, Claude Code, GitHub
Copilot, Codex**, or any frontier model. It installs the package, wires the stylesheet, reads the
live docs and machine catalog, records the conventions in your repo's agent-rules file, and
renders a first chart to verify. Works on a fresh repo or an existing one.

<div className="agent-prompt">

```md title="Paste into your agent"
Set up **@microcharts/react** in this repo — word-sized, zero-dependency React charts. Work through every step; don't stop to ask.

## 1 · Install

- Add `@microcharts/react` (peer dependency: React 18 or 19; no other runtime deps).
- Import the stylesheet once, at your app root: `import "@microcharts/react/styles.css"`

## 2 · Learn the API

Read the live docs before writing any chart code:

- Full docs → https://microcharts.dev/llms-full.txt
- Catalog → https://microcharts.dev/catalog.json

Pick a chart by the decision it must show, then copy its exact import path and props from the catalog.

## 3 · Record the conventions

Add a `## microcharts` section to `AGENTS.md` (create it if missing — Cursor, Copilot and Codex read it; for Claude Code, run `ln -s AGENTS.md CLAUDE.md`). Capture these rules:

- Import per subpath, e.g. `@microcharts/react/sparkline`. The default export is static — RSC-safe, zero client JS. Use the `/interactive` subpath only for hover or keyboard.
- `data` alone always renders. One grammar on every chart: `data`, `domain`, `color`, `title`, `summary`, `format`, `positive`, `label`, `dots`. Chart-specific props are in `catalog.json`.
- Accessibility is automatic (`role="img"` + a generated summary). Inline in a sentence: wrap the mark in `<span className="mc-inline">` and pass `summary={false}`.
- Theme with `--mc-*` variables or a preset attribute `data-mc-theme="editorial | mono | vivid | dark | print | eink"` (or `defineTheme` from `@microcharts/react/theme` for a derived palette). Never hardcode colors; charts paint no background — place them on a surface with contrast.
- `width` and `height` are viewBox units; fill a container with `style={{ width: "100%", height: "auto" }}`.
- Format numbers with one `format` prop (`Intl.NumberFormatOptions` or `(n) => string`) plus `locale`. Fix the scale with `domain={[min, max]}`. Share one scale across small multiples with `SparkGroup`.
- Annotations are children: `Threshold`, `TargetZone`, `Marker`, `Callout` from `@microcharts/react/annotations`.
- Never add a runtime dependency to render a chart. No pie or gauge — use `Bullet`, `SegmentedBar`, or `MicroDonut`.

## 4 · Verify

Render `<Sparkline data={[3, 5, 4, 8, 6, 9]} title="Weekly revenue" />` in a real page, run the app or build, and confirm it appears with styles applied.
```

## The shared grammar

One idea runs through the whole catalog: **the same prop name means the same thing on every
chart.** Learn these once and they transfer everywhere — a new chart type is a new data shape,
never a new vocabulary. `data` alone always renders something correct; everything else is opt-in.

| Prop       | Type                                        | What it does                                                                                                                              |
| ---------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `data`     | `(number \| null)[]`                        | The series. `null` / `NaN` are gaps, never zeros. The one required prop.                                                                  |
| `domain`   | `[min, max]`                                | Fix the value range instead of auto-fitting — see [Formatting & scale](/docs/formatting#scale-the-domain-decision).                       |
| `color`    | `string`                                    | Mark color: any CSS color or a token (`"var(--mc-accent)"`). Semantic tokens keep their meaning — see [Theming](/docs/theming).           |
| `title`    | `string`                                    | A visible title, wired into the chart's accessible name.                                                                                  |
| `summary`  | `string \| false`                           | Override the auto-generated accessible sentence, or pass `false` to mark the chart decorative — see [Accessibility](/docs/accessibility). |
| `format`   | `Intl.NumberFormatOptions \| (n) => string` | How numbers render in labels and summaries — see [Formatting & scale](/docs/formatting).                                                  |
| `positive` | `"up" \| "down"`                            | Which direction is good, so color and arrows point the honest way (lower latency is `"down"`).                                            |
| `label`    | _per chart_                                 | A short direct label next to the mark, in a reserved gutter — never an axis or legend.                                                    |
| `dots`     | _per chart_                                 | Which individual points to emphasize (e.g. `"minmax"` on a line).                                                                         |

Not every prop applies to every chart — a bar chart has no `dots` — but wherever a concept
exists, its prop name and meaning are always these. Each one has a deeper home:
[Formatting & scale](/docs/formatting) owns `format` and `domain`, [Theming](/docs/theming) owns
`color`, and [Accessibility](/docs/accessibility) owns `summary`. Every chart also takes the
layout props (`width`, `height`, `className`, `style`, `id`; see [Sizing](/docs/sizing)) and a
few props specific to its own shape, listed in the prop table on each chart's page. To place
charts in real UI — or render several on one shared scale with `SparkGroup` — see
[Composition](/docs/composition).

## Add interactivity

Need hover, keyboard navigation, or live announcements? Import the same chart from its
`/interactive` entry. Everything else — props, output, accessibility — is identical; you just
opt into the client component where it matters.

```tsx
import { Sparkline } from "@microcharts/react/sparkline/interactive";

<Sparkline data={[3, 5, 4, 8, 6, 9]} title="Weekly revenue" />;
```

## Animate on mount (optional)

Every interactive entry also takes an `animate` prop — the chart draws on instead of appearing
instantly. It's off by default, and inert on the server and on hydrated server HTML, so it never
fights SSR or flashes over painted content; a fresh client-side mount is what plays it. Wire the
engine once, client-side, then opt in per chart:

```tsx
import "@microcharts/react/motion"; // once, client-side

<Sparkline data={[3, 5, 4, 8, 6, 9]} title="Weekly revenue" animate />;
```

`prefers-reduced-motion` wins unconditionally — a reader who asked for less motion gets the
finished chart, never the entrance.

## Import paths

Import each chart from its own subpath so you only ship what you use. Every chart in the catalog
follows the same two-entry pattern — a static default and an `/interactive` twin:

| Chart        | Static                             | Interactive                                    |
| ------------ | ---------------------------------- | ---------------------------------------------- |
| Sparkline    | `@microcharts/react/sparkline`     | `@microcharts/react/sparkline/interactive`     |
| SparkBar     | `@microcharts/react/sparkbar`      | `@microcharts/react/sparkbar/interactive`      |
| Delta        | `@microcharts/react/delta`         | `@microcharts/react/delta/interactive`         |
| Bullet       | `@microcharts/react/bullet`        | `@microcharts/react/bullet/interactive`        |
| ActivityGrid | `@microcharts/react/activity-grid` | `@microcharts/react/activity-grid/interactive` |

Every other chart uses the same shape — see [All charts](/docs/charts) for the full catalog,
each page listing its own import path and props.
