Performance is a promise, not a marketing line. Every figure below is produced by a command
you can run yourself.

## Size

Each chart is imported from its own subpath, so you ship only what you use. Sizes are gzip,
measured in CI by `pnpm size` and gated — a chart that grows past budget fails the build.

| Chart        | Static  | Interactive |
| ------------ | ------- | ----------- |
| Sparkline    | 3.62 kB | 4.61 kB     |
| SparkBar     | 2.78 kB | 3.69 kB     |
| Delta        | 0.92 kB | 1.17 kB     |
| Bullet       | 1.66 kB | 2.02 kB     |
| ActivityGrid | 2.08 kB | 3.25 kB     |

Across all 98 charts the static entries span 0.9–3.6 kB with a median of 2.3 kB; every
chart page shows its own measured number in the hero demo's header.

The whole library carries **zero runtime dependencies** — no chart engine, no D3. That
constraint is enforced by CI, permanently.

## Server rendering

Static charts are hook-free and listener-free, so they render on the server to plain SVG
with no client JavaScript. Throughput, measured by `pnpm bench`:

| Charts | Time    | Per chart | Payload |
| ------ | ------- | --------- | ------- |
| 100    | 1.0 ms  | 0.010 ms  | ~550 B  |
| 500    | 5.4 ms  | 0.011 ms  | ~550 B  |
| 1000   | 10.8 ms | 0.011 ms  | ~550 B  |

A table with 500 sparklines becomes HTML in about five milliseconds, and none of it ships
JavaScript to the browser.

## Reproduce it

```bash
git clone https://github.com/ganapativs/microcharts
pnpm install
pnpm bench   # SSR throughput → bench/results.json
pnpm size    # gzip budgets → measured actuals
```
